Kita mulai Semester 2 dengan cara menyimpan sekumpulan data

Selama Semester 1, kamu sudah membuat layar aplikasi, memakai komponen di Designer, dan menghubungkan tindakan pengguna ke Blocks. Sekarang kita akan belajar mengatur data yang jumlahnya lebih dari satu. Contoh yang dekat dengan keseharian adalah daftar belanja.

Di akhir sesi, kamu akan membuat aplikasi Daftar Belanja Cerdas. Data barangnya disusun sebagai List lalu ditampilkan lewat komponen ListView. Saat layar dibuka, event Screen1.Initialize akan menjalankan perintah untuk mengisi daftar tersebut.

Target kita hari ini masih sederhana: daftar statis berisi lima barang. Artinya, isi daftar ditentukan di Blocks saat membuat aplikasi. Fitur menambah atau menghapus barang lewat input pengguna belum dikerjakan di sesi ini.

Empat tahapan yang akan kamu lewati

Kita tidak langsung menyusun Blocks. Pertama, kamu perlu tahu mengapa List digunakan dan apa arti setiap posisi di dalamnya. Setelah itu, kita siapkan tampilan di Designer supaya data punya tempat untuk ditampilkan.

Setelah tampilan jadi, kita pindah ke Blocks. Di sana, kita akan memakai event Screen1.Initialize, perintah set lvBelanja.Elements to, dan blok make a list. Terakhir, kita menjalankan aplikasi menggunakan AI2 Companion atau emulator.

Jika hasilnya sudah benar, simpan project dan ekspor file .aia. File inilah yang menyimpan source project sehingga bisa diperiksa atau dikembangkan lagi. Checkout Quiz Sesi 25 dikerjakan melalui LMS, bukan di slide ini.

Mengapa tidak memakai variabel terpisah?

Coba bayangkan kamu membuat aplikasi daftar belanja, tetapi setiap barang harus punya satu variabel yang berbeda: barang1, barang2, sampai barang20. Cara tersebut mungkin masih terlihat mudah untuk dua atau tiga barang, tetapi akan merepotkan ketika jumlahnya banyak.

List membantu kita mengelompokkan beberapa nilai yang berkaitan dalam satu struktur. Pada contoh ini, semua nilainya adalah nama barang. Urutannya juga jelas, sehingga kita tahu barang mana yang pertama, kedua, dan seterusnya.

List tidak otomatis menghitung harga, membuat tombol, atau menyimpan data secara permanen. List hanya menjadi struktur data. Agar barang terlihat pada layar HP, kita masih memerlukan komponen tampilan seperti ListView.

List adalah wadah untuk beberapa nilai

Dalam pemrograman, setiap nilai yang berada di dalam List disebut elemen. Karena elemen disimpan berurutan, kita bisa mengenali sebuah elemen dari posisinya. Inilah dasar struktur data yang akan terus dipakai pada materi berikutnya.

Kita sering menyebut List ketika membahas kumpulan data di MIT App Inventor. Istilah array juga sering dipakai untuk membahas data berurutan, meskipun dalam beberapa bahasa pemrograman keduanya mempunyai aturan berbeda. Untuk project ini, fokusmu adalah blok make a list.

Pada aplikasi Daftar Belanja Cerdas, elemen yang digunakan berupa teks: ayam, minyak, beras, garam, dan sabun. Semua elemen akan ditampilkan sesuai urutan di dalam List.

Posisi bukan isi

Elemen adalah nilai yang disimpan, misalnya kata beras. Indeks adalah nomor posisi elemen dalam List. Pada contoh ini, beras berada di indeks 3, sedangkan sabun berada di indeks 5. Angka indeks tidak menunjukkan jumlah atau harga barang.

Di MIT App Inventor, elemen pertama mempunyai indeks 1. Karena kita menyimpan lima elemen, indeks yang tersedia adalah 1 sampai 5. Beberapa bahasa pemrograman lain, seperti Python, sering menggunakan indeks 0 untuk elemen pertama. Jangan sampai aturan dari bahasa lain terbawa ke project MIT App Inventor.

Urutan elemen penting. Jika sabun dipindah ke posisi kedua, indeks 2 akan berisi sabun. Artinya, sebuah indeks menunjuk posisi saat ini, bukan nama barang yang selalu tetap.

Latihan membaca posisi List

Gunakan tombol indeks untuk melihat bagaimana satu angka menunjuk satu elemen. Ketika menekan 1, hasilnya ayam. Ketika menekan 3, hasilnya beras. Ketika menekan 5, hasilnya sabun. Kamu sedang berlatih memahami hubungan antara posisi dan isi.

Mengganti teks suatu elemen tidak otomatis mengubah posisi elemen lain. Contohnya, jika nama barang pada indeks 1 diganti menjadi telur tetapi urutannya tidak diubah, indeks 2 tetap minyak. Berbeda halnya jika elemen dipindahkan ke posisi lain: isi pada indeks yang terlibat bisa berubah.

Latihan ini hanya simulasi pemahaman indeks di learning slides. Project inti Sesi 25 tidak meminta kamu membuat tombol pemilih indeks di aplikasi MIT App Inventor.

Urutan menentukan apa yang kamu temukan pada suatu indeks

Sebelum bertukar posisi, minyak berada pada indeks 2 dan sabun pada indeks 5. Setelah keduanya ditukar, susunannya menjadi ayam, sabun, beras, garam, minyak. Oleh sebab itu, elemen pada indeks 2 adalah sabun.

Memahami posisi membantu kita saat nanti belajar mengambil, mengganti, menambah, atau menghapus item List. Untuk sesi ini, kamu hanya perlu bisa membaca posisi dengan benar dan memahami bahwa List mempunyai urutan.

Jika jawabanmu masih tertukar, tulis lima nama barang di kertas lalu beri nomor 1–5. Tukar posisi dua kartu barang tanpa mengubah nomor kartunya. Kamu akan langsung melihat mengapa nilai di indeks 2 berubah.

Bedakan tempat menyimpan data dan tempat menampilkan data

List adalah struktur data. Pengguna tidak bisa melihat sebuah List hanya karena kamu sudah menyusun blok make a list. Data tersebut perlu dihubungkan dengan komponen tampilan.

ListView adalah salah satu komponen pada Designer MIT App Inventor untuk menunjukkan kumpulan item. Pada project kita, nama komponennya adalah lvBelanja. Properti Elements menentukan daftar teks yang ditampilkan oleh komponen tersebut.

Kalimat pengingat yang mudah: List menyimpan isi; ListView memperlihatkan isi. Jika List sudah benar tetapi ListView kosong, masalahnya mungkin bukan pada nama barang, melainkan pada koneksi Blocks ke property Elements.

Satu konsep, dua cara belajar

Guru bisa memilih aktivitas dengan kartu barang atau pengamatan aplikasi contoh. Keduanya melatih konsep yang sama, yaitu urutan data serta perbedaan List dengan ListView. Jika memakai kartu, nomor 1–5 mewakili indeks, sedangkan tulisan nama barang mewakili elemen.

Jika mengamati aplikasi, kamu bisa melihat hasil akhir ListView tanpa perlu membangun Blocks lebih dahulu. Catat nama item yang tampil dari atas ke bawah. Coba jelaskan mengapa urutan pada layar mengikuti urutan data.

Kamu tidak perlu melakukan kedua opsi sekaligus. Setelah aktivitas, pastikan kamu bisa menjelaskan satu kalimat ini: data disusun sebagai List dan diperlihatkan menggunakan ListView.

Bangun dulu tempat datanya akan terlihat

Di MIT App Inventor, tab Designer digunakan untuk menambahkan komponen serta mengatur tampilan. Pada project ini kita memakai dua Label, satu VerticalArrangement, dan satu ListView. Nama komponennya perlu sesuai agar mudah ditemukan ketika berpindah ke Blocks.

LabelJudul menampilkan tulisan Daftar Belanja Cerdas. ArrUtama membantu mengelompokkan komponen secara vertikal. Di dalamnya ada LabelPetunjuk yang memberi instruksi singkat dan lvBelanja yang akan menampilkan data.

Perhatikan huruf besar dan kecil pada nama seperti lvBelanja. Jika kamu tidak melakukan rename, MIT App Inventor akan menggunakan nama bawaan seperti ListView1, sehingga gambarnya tampak berbeda dengan referensi dan kamu mungkin mencari blok yang salah.

Periksa hierarki, bukan cuma keberadaan komponen

Di panel Components, kamu seharusnya melihat LabelJudul sebagai bagian dari Screen1. Lalu ada ArrUtama, dan di dalam Arrangement ini terdapat LabelPetunjuk serta lvBelanja. Susunan tersebut menjadikan petunjuk dan daftar berada dalam satu kelompok tata letak.

LabelJudul dapat diberi teks Daftar Belanja Cerdas. LabelPetunjuk diisi Berikut daftar barang belanja:. Untuk ListView, kamu tidak perlu mengetik semua barang secara manual di Designer karena data akan diberikan lewat Blocks.

Kalau sebuah komponen tampak tidak berada di tempat yang kamu inginkan, cek posisinya pada panel Components. Geser ke dalam Arrangement yang benar dan sesuaikan Width atau Height bila perlu. Tujuan kita adalah tampilan sederhana yang mudah dibaca.

Apa yang seharusnya terlihat ketika aplikasi dibuka?

Pada bagian atas ada judul aplikasi. Di bawahnya tertulis petunjuk singkat, lalu lima item ditampilkan berurutan dari atas ke bawah. Tampilan daftar inilah hasil dari komponen lvBelanja. Tidak diperlukan tombol untuk membuat daftar muncul karena logikanya akan diletakkan di event Screen1.Initialize.

Jika tampilan di HP-mu mempunyai ukuran teks atau warna yang berbeda, itu bukan masalah utama selama isi dan urutan barangnya benar serta mudah dibaca. Komponen ListView pada file referensi guru memiliki pengaturan visual tertentu, tetapi tujuan koding sesi ini berfokus pada koneksi data.

Jangan menambahkan fitur input, perhitungan harga, atau tombol hapus hanya demi membuat aplikasi terlihat lebih canggih. Kita sedang mempelajari dasar pengelolaan List terlebih dahulu.

Checkpoint sebelum menyusun Blocks

Lebih mudah memperbaiki tampilan sekarang daripada saat kita sudah menyambungkan Blocks. Periksa satu per satu nama dan posisi komponen di panel Components, bukan hanya apa yang terlihat di Viewer.

Komponen ListView boleh belum menampilkan ayam, minyak, atau barang lain pada tahap ini. Itu wajar, karena kita belum menghubungkannya ke List melalui event dan Blocks. Yang penting komponen dan propertinya siap digunakan.

Jika daftar nantinya tidak muncul, nama dan keberadaan lvBelanja adalah salah satu hal pertama yang harus diperiksa. Screenshot contoh di learning slides menunjukkan nama yang harus kamu cari di Blocks.

Baca logika Blocks dari pemicu sampai hasil

Di MIT App Inventor, kita sering memakai pola event → action → output. Event adalah kejadian yang memulai proses. Action adalah perintah yang dijalankan. Output adalah hasil yang terlihat oleh pengguna.

Untuk project ini, event-nya adalah Screen1.Initialize, yaitu saat Screen1 mulai dibuka. Action-nya adalah menetapkan lvBelanja.Elements menggunakan sebuah List. Output-nya adalah lima nama barang muncul di layar.

Ketiga blok harus tersambung. Blok make a list yang berdiri sendiri belum melakukan apa-apa terhadap komponen. Begitu pula event Initialize yang kosong belum memerintahkan aplikasi menampilkan daftar.

Event yang bekerja otomatis ketika layar dimulai

when Screen1.Initialize do adalah blok event yang berada pada bagian Blocks milik Screen1. Event ini berjalan ketika Screen1 mulai diinisialisasi, sehingga cocok untuk menyiapkan isi daftar begitu layar pertama muncul.

Perhatikan ruang kosong pada bagian do. Ruang itu bukan tempat mengetik nama barang secara langsung. Kita perlu memasukkan blok perintah, yaitu set lvBelanja.Elements to. Blok ini akan menentukan apa yang harus ditampilkan oleh ListView.

Jika kamu hanya menaruh blok Initialize tanpa perintah apa pun di dalamnya, aplikasi tetap bisa dibuka tetapi daftar belanja tidak otomatis terisi dari kode tersebut. Jadi, event adalah pemicu, bukan data List-nya.

Lima elemen di dalam satu blok Lists

Blok make a list tersedia pada kategori Lists di Blocks. Blok ini menggabungkan beberapa nilai menjadi satu kumpulan. Pada gambar, nilai-nilainya adalah teks ayam, minyak, beras, garam, dan sabun.

Untuk membuat lima slot, gunakan ikon roda gigi kecil pada blok make a list, kemudian atur jumlah item yang dibutuhkan. Setelah itu, ambil blok teks dari kategori Text dan ketik satu nama barang pada setiap slot.

Urutan dari atas ke bawah adalah urutan dalam List. Elemen pertama menjadi indeks 1, elemen kelima menjadi indeks 5. Pastikan tidak ada slot kosong, salah eja, atau urutan tertukar jika kamu ingin hasilnya sama seperti contoh project guru.

Properti Elements adalah jembatan antara data dan layar

Blok hijau set lvBelanja.Elements to bisa ditemukan melalui drawer komponen lvBelanja di bagian Blocks. Perintah set ... to berarti kita memberikan nilai baru kepada suatu properti. Di sini propertinya adalah Elements.

Dalam project ini, nilai yang diberikan adalah hasil blok make a list. Dengan demikian, ListView akan memiliki lima item untuk ditampilkan. Perhatikan bagaimana ujung blok List terpasang pada soket kosong setelah kata to.

Blok ini tetap harus berada di dalam event Screen1.Initialize agar perintah berjalan ketika aplikasi dibuka. Jika blok set Elements terpisah dan tidak dipanggil, daftar belum tentu terisi melalui alur program kita.

Baca keseluruhan Blocks sebagai satu kalimat

Sekarang gabungkan tiga potongan sebelumnya. Bagian terluar adalah when Screen1.Initialize. Di bagian do ada perintah set lvBelanja.Elements to. Pada soket nilainya terpasang blok make a list yang berisi lima teks.

Kamu tidak perlu menulis kode teks seperti Python. Di MIT App Inventor, kita membangun alur dengan menyambungkan bentuk Blocks yang sesuai. Pastikan sambungannya benar dan tidak ada bagian yang menggantung terpisah.

Bila aplikasi belum menampilkan daftar, periksa hubungan tiga bagian tersebut secara berurutan. Source project sesi_25_Daftar_Belanja_Cerdas.aia menggunakan susunan Blocks yang sama dengan gambar lengkap ini.

Hubungkan event, action, dan tampilan

Ketika aplikasi dijalankan, MIT App Inventor menyiapkan Screen1 dan komponen yang ada di dalamnya. Saat event Initialize berlangsung, perintah di bagian do dijalankan. Perintah tersebut memberikan List lima barang ke properti Elements milik lvBelanja.

ListView kemudian dapat menampilkan item yang telah diterimanya sesuai urutan. Kalau List berisi lima teks, secara normal ListView akan menampilkan lima item. Tidak ada perhitungan harga, pengurutan otomatis, atau pemilihan barang tertentu di project dasar ini.

Pemahaman alur ini lebih penting daripada sekadar menyalin gambar. Kamu seharusnya bisa menjelaskan kenapa daftar muncul tanpa tombol dan apa yang berubah jika salah satu teks di dalam List diganti.

Langkah project dari awal sampai bisa dijalankan

Buka MIT App Inventor dan pilih membuat project baru. Beri nama yang mudah dikenali, misalnya DaftarBelanjaCerdas. Di Designer, susun komponen sesuai peta yang sudah dipelajari dan lengkapi teks judul serta petunjuk.

Pindah ke Blocks. Ambil event Screen1.Initialize. Temukan drawer lvBelanja, lalu pilih blok untuk mengatur properti Elements. Tempatkan di dalam event. Berikutnya, dari kategori Lists ambil make a list, atur lima slot, dan masukkan teks barang.

Setelah Blocks tersambung, hubungkan MIT App Inventor ke AI2 Companion sesuai panduan kelas. Saat aplikasi dibuka, amati apakah kelima barang tampil. Periksa urutannya sebelum melanjutkan checkpoint berikutnya.

Mengapa urutannya seperti itu?

Urutan pertama adalah event Screen1.Initialize, karena kita perlu tahu kapan perintah dijalankan. Selanjutnya adalah perintah set lvBelanja.Elements to, sebab inilah tindakan yang akan mengubah daftar yang ditampilkan. Terakhir, data yang diberikan adalah blok make a list.

Secara visual, make a list memang menempel di dalam blok set Elements, bukan diletakkan sesudahnya secara terpisah. Latihan urutan ini membantu kamu membaca hubungan antarbagiannya sebagai event → aksi → data yang dipakai aksi.

Jika masih bingung, kembali ke gambar Blocks lengkap. Coba tunjuk menggunakan jari bagian event, perintah set, dan data List. Itu adalah tiga bagian yang perlu kamu ingat saat debugging.

Perubahan isi tidak selalu mengubah urutan

Ketika kamu mengganti teks pada elemen ketiga dari beras menjadi telur, List-nya tetap memiliki lima elemen. Posisi 1 masih ayam, posisi 2 masih minyak, posisi 4 masih garam, dan posisi 5 masih sabun. Hanya nilai pada indeks 3 yang berubah menjadi telur.

Di MIT App Inventor, perubahan untuk project statis dilakukan dengan mengedit blok teks yang terpasang pada make a list, kemudian menjalankan atau menyegarkan aplikasi. Simulasi di samping hanya menunjukkan perilaku yang bisa kamu harapkan.

Fitur untuk mengubah isi List langsung oleh pengguna ketika aplikasi sedang berjalan adalah pembelajaran tahap berikutnya. Jangan mencampur latihan ini dengan penambahan TextBox, Button, atau TinyDB di sesi 25.

Menguji apakah kamu paham fungsi, bukan hanya nama blok

Perintah set lvBelanja.Elements to digunakan untuk menetapkan isi properti Elements. Nilai yang kita berikan berupa sebuah List, dan ListView menampilkan item-item tersebut. Karena itu, hubungan blok ini adalah hubungan antara struktur data dan tampilan.

Perintah tersebut tidak menyimpan file .aia. Menyimpan project merupakan tindakan terpisah lewat menu Projects pada editor. Blok ini juga tidak menghitung harga atau menambahkan barang baru dari pengguna.

Kalau jawabanmu tadi salah, ingat kembali perbedaannya: make a list menyiapkan data, sementara set lvBelanja.Elements memasang data itu pada komponen tampilan.

Testing berarti membandingkan hasil harapan dengan hasil nyata

Jalankan aplikasi di HP melalui AI2 Companion, atau emulator bila fasilitas kelas menggunakannya. Yang pertama diuji adalah apakah aplikasi bisa dibuka dan kelima item langsung terlihat. Lalu cek jumlah dan urutannya secara teliti.

Jika ada lima item tetapi urutannya berbeda, project belum sepenuhnya sesuai contoh. Kembali ke urutan teks di make a list lalu jalankan ulang. Jika daftar kosong, cek event Initialize dan sambungan property Elements. Jika Companion tidak terkoneksi, periksa dahulu koneksi atau pengaturan pengujian.

Pada pengujian ini, kamu tidak perlu membuktikan fitur klik item, tambah item, atau hapus item. Fitur-fitur tersebut belum termasuk hasil wajib aplikasi statis di Sesi 25.

Langkah sederhana untuk mencari bug

Saat sebuah ListView kosong, pertama pastikan komponen lvBelanja benar-benar ada dan tampil di Designer. Kedua, pastikan event Screen1.Initialize berisi perintah set lvBelanja.Elements to. Ketiga, pastikan soketnya diisi blok make a list yang memiliki teks.

Jika ketiga bagian itu sudah benar, periksa apakah project sudah di-refresh di AI2 Companion atau emulator. Kadang siswa sudah mengubah Blocks tetapi melihat hasil tampilan lama karena koneksi Companion belum diperbarui.

Perbaiki satu kemungkinan dulu lalu uji lagi. Cara ini lebih efektif daripada langsung menghapus seluruh Blocks atau mengganti semua komponen tanpa tahu sumber kesalahannya.

Jenis kesalahan menentukan langkah perbaikannya

Jika jumlah item kurang, masalah paling mungkin berada pada jumlah slot atau nilai di dalam make a list. Gunakan roda gigi untuk mengecek jumlah item dan pastikan tiap slot terisi. Tidak perlu membuat komponen baru.

Jika jumlah item sudah lima tetapi urutannya salah, cocokkan elemen pertama hingga kelima dengan urutan target. Ingat bahwa List mengikuti urutan data yang kamu susun, bukan menyortir otomatis berdasarkan abjad.

Jika daftar tidak menampilkan apa-apa, kembali ke alur event dan property. Baca dari luar: apakah event benar, apakah perintah set terpasang, dan apakah blok List tersambung? Setelah perbaikan, lakukan re-test agar kamu tahu bahwa bug benar-benar sudah hilang.

Mengapa daftar belanja berkaitan dengan literasi finansial?

Daftar belanja bukan hanya soal menyebut barang. Membuat daftar membantu kita memikirkan apa yang perlu dibeli, terutama saat uang yang tersedia terbatas. Kita bisa membedakan barang yang benar-benar dibutuhkan dari barang yang sekadar menarik perhatian.

Contohnya, jika keluarga sudah memiliki beras yang cukup, mungkin beras tidak perlu dibeli lagi. Sebaliknya, sabun yang habis dapat menjadi kebutuhan lebih mendesak. Keputusan tetap bergantung pada situasi masing-masing, bukan karena suatu barang selalu dianggap kebutuhan atau selalu dianggap keinginan.

Aplikasi pada sesi ini hanya menampilkan nama barang. Kita belum memasukkan harga, saldo, atau kategori otomatis. Pemahaman perencanaan belanja menjadi konteks dari project, bukan klaim fitur yang belum ada.

Latihan yang sederhana juga perlu kebiasaan digital yang baik

Walaupun aplikasi hanya berisi daftar belanja, tetap biasakan memakai data yang aman. Kita tidak membutuhkan identitas pribadi, alamat rumah, nomor rekening, atau informasi pembayaran untuk memperlihatkan bagaimana ListView bekerja.

File .aia berisi project MIT App Inventor beserta komponen dan Blocks-nya. File ini bisa dipakai untuk melanjutkan proyek di kemudian hari, sehingga sebaiknya disimpan dengan nama yang jelas dan dibagikan hanya lewat kanal pengumpulan yang ditetapkan guru.

Perhatikan juga akses ketika membagikan tautan Drive atau file lain. Jangan mengubah akses menjadi publik hanya untuk mempermudah pengumpulan kecuali memang diminta sesuai kebijakan kelas.

Kumpulkan source project, bukan hanya screenshot

Setelah project berhasil diuji, simpan project di MIT App Inventor lalu gunakan menu Projects untuk mengekspor source project sebagai file .aia. Nama perintah ekspor dapat berbeda sedikit tergantung versi editor. Intinya, pilih Export selected project (.aia) atau opsi ekspor source setara.

Pastikan file yang diunduh mempunyai ekstensi .aia, bukan hanya gambar screenshot atau file instalasi .apk. Screenshot boleh menjadi bukti tampilan bila guru memintanya, tetapi tidak menggantikan source project ketika instruksi tugas menyebut .aia.

Buka tugas pada LMS UOB My Digital Space, unggah file sesuai petunjuk yang diberikan, lalu tekan tombol Submit/Kirim. Mengunggah file belum selalu berarti tugas sudah terkirim. Periksa status pengumpulan sebelum meninggalkan halaman.

Yang perlu kamu bawa dari Sesi 25

Pada sesi ini kamu belajar bahwa sebuah List menyimpan beberapa elemen dalam satu struktur data yang berurutan. Setiap elemen mempunyai posisi atau indeks. Pada MIT App Inventor, indeks dimulai dari 1. Kamu juga belajar bahwa ListView adalah komponen tampilan, bukan List itu sendiri.

Di project Daftar Belanja Cerdas, kita menggunakan tiga bagian Blocks yang saling terhubung: Screen1.Initialize, set lvBelanja.Elements to, dan make a list. Kombinasi ini membuat lima barang langsung terlihat ketika aplikasi dibuka.

Jika belum selesai, periksa lagi checkpoint dan test case sebelum submit. Setelah file .aia terkumpul, lanjutkan Checkout Quiz Sesi 25 secara mandiri di LMS. Pada sesi berikutnya, kamu akan mempelajari cara membuat List lebih interaktif, termasuk perubahan item secara dinamis.
