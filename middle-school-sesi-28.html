Urutan validasi dari Blocks asli

Event tombol Top-Up dalam .aia memeriksa tiga kondisi sebelum berhitung. Pertama, teks kosong atau hanya spasi ditolak. Kedua, is a number? menolak input bukan angka. Ketiga, nominal harus lebih dari 0. Jika semua syarat terpenuhi, aplikasi menjumlahkan nominal dengan global saldo, memanggil PerbaruiSaldo, dan mengosongkan TextBox. Jika input tidak valid, angka saldo tidak berubah.

Ikuti alur cabang pada screenshot

  1. Kosong atau spasi? trim + length = 0 → Notifier: Masukkan nominal terlebih dahulu.
  2. Bukan angka? is a number? → Notifier: Nominal harus berupa angka yang valid.
  3. Angka tidak lebih dari 0? → Notifier: Nominal harus lebih dari 0.
  4. Valid? Hitung global saldo + txtNominal.Text, panggil PerbaruiSaldo, lalu kosongkan TextBox.

Tiga pengecekan dilakukan sebelum saldo berubah. Coba uji 20000, 0, dan input kosong.

Peringatan tanpa mengubah saldo

Pada kasus input kosong, blok tidak melanjutkan perhitungan. NumbersOnly pada Designer membantu, tetapi tidak otomatis memeriksa seluruh kondisi tersebut.

Validasi Bayar lebih lengkap

Event Bayar memakai tiga validasi awal yang sama seperti Top-Up. Bedanya, sebelum pengurangan terdapat kondisi global saldo ≥ nominal. Jika saldo cukup, program mengurangi nilai pada variabel, memanggil prosedur untuk menyimpan dan menampilkan hasil, lalu membersihkan input. Jika saldo kurang, Notifier menolak pembayaran dan saldo tetap sama. Ini mencegah saldo simulasi menjadi negatif.

Cek empat hal sebelum mengurangi saldo

  1. Apakah input kosong? Jika iya, tampilkan Notifier.
  2. Apakah input berupa angka? Jika tidak, tolak.
  3. Apakah nominal lebih dari 0? Jika tidak, tolak.
  4. Apakah global saldo ≥ txtNominal.Text? Jika tidak, Notifier menampilkan Saldo tidak cukup untuk pembayaran.

Jika semua syarat benar, lakukan saldo − nominal, panggil PerbaruiSaldo, lalu kosongkan input. Contoh: saldo 55000 dan Bayar 70000 harus ditolak tanpa mengubah saldo.
