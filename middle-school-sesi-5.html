Project yang Akan Dibuat

Di sesi ini, kalian akan membuat aplikasi sederhana bernama Aplikasi Sapaan. Aplikasi ini terlihat sederhana, tetapi konsepnya penting banget untuk semua aplikasi yang memakai data dari user.

Alurnya seperti ini: user mengetik nama, aplikasi menyimpan nama itu ke dalam variabel, lalu nama tersebut dipakai lagi untuk membuat kalimat sapaan. Jadi aplikasi tidak hanya menampilkan teks statis, tetapi memakai data yang baru dimasukkan.

Fokus sesi

Kita akan belajar variabel, global variable, TextBox, Label, dan cara menggabungkan teks dengan data user menggunakan blok join.

Alur Belajar

Sesi ini fokus pada cara aplikasi menyimpan dan memakai data. Konsep ini akan sering dipakai di project berikutnya, terutama saat aplikasi perlu menghitung, mengecek pilihan user, atau menampilkan hasil yang berbeda-beda.

Kalau aplikasi tidak punya tempat menyimpan data, aplikasi akan sulit memberi respons yang personal. Misalnya, aplikasi hanya bisa menampilkan “Halo!” tanpa tahu siapa nama user. Dengan variabel, aplikasi bisa menampilkan “Halo, Raka!” atau “Halo, Nisa!” sesuai input.

Yang akan dikuasai

  1. Membedakan input dari TextBox dan output di Label.
  2. Membuat global variable.
  3. Menyimpan isi TextBox ke variabel.
  4. Mengambil isi variabel untuk membuat sapaan.
  5. Menguji aplikasi dengan beberapa data berbeda.

Kenapa Data Perlu Disimpan?

Banyak aplikasi terasa lebih hidup karena bisa memakai data dari user. Contohnya, aplikasi belajar menampilkan nama siswa, game menyimpan nama pemain, atau aplikasi keuangan menampilkan target tabungan yang pernah diisi.

Agar data bisa dipakai lagi, aplikasi membutuhkan tempat penyimpanan sementara. Dalam programming, tempat seperti itu disebut variabel. Pada sesi ini, kita memakai variabel untuk menyimpan nama yang diketik user.

Contoh sederhana

Tanpa variabel, aplikasi hanya bisa menampilkan sapaan umum. Dengan variabel, aplikasi bisa menampilkan sapaan yang mengikuti input user.

Variabel sebagai Kotak Memori

Bayangkan kalian punya kotak kecil dengan label “nama”. Ketika sticky note bertuliskan “Budi” dimasukkan ke kotak itu, kita bisa membuka kotaknya kapan saja untuk membaca isi “Budi”.

Di aplikasi, variabel bekerja mirip seperti itu. Variabel punya nama sebagai label, lalu punya nilai sebagai isi. Nilainya bisa berubah saat aplikasi berjalan. Hari ini, isi variabel akan berasal dari TextBox yang diketik user.

Kalimat penting

Nama variabel tidak sama dengan isi variabel. global nama adalah label kotaknya, sedangkan Budi adalah isi yang sedang disimpan.

Mencoba Cara Kerja Variabel

Simulasi di kiri menunjukkan alur yang akan terjadi di App Inventor. TextBox adalah tempat user mengetik. Saat tombol ditekan, isi TextBox disalin ke dalam variabel global nama.

Setelah disimpan, data tersebut bisa dipakai lagi. Misalnya untuk ditampilkan di Label, digabungkan dengan kata “Halo,”, atau bahkan dibacakan dengan Text-to-Speech sebagai challenge.

Catatan

Variabel di project ini menyimpan data sementara. Jika aplikasi ditutup atau di-reset, isi variabel bisa kembali kosong.

Mengapa Memakai Global Variable?

Di MIT App Inventor, global variable dapat dipakai di beberapa blok pada Screen yang sama. Untuk project ini, kita membuat global nama agar data nama bisa disimpan saat tombol ditekan, lalu dipakai lagi untuk membuat sapaan.

Tiga aksi yang perlu diingat adalah initialize, set, dan get. Initialize membuat variabel, set mengganti isinya, dan get mengambil isi yang tersimpan.

Contoh alur

Awalnya global nama berisi kosong. Setelah user mengetik “Nisa” dan menekan tombol Sapa!, global nama berubah menjadi “Nisa”.

Input dan Output di UI

TextBox dipakai untuk menerima data dari user. Karena itu, TextBox termasuk komponen input. Pada project ini, TextBox diberi nama txtNama agar jelas bahwa isinya adalah nama user.

Label dipakai untuk menampilkan hasil. Label lblHasil akan berubah setelah tombol Sapa! ditekan. Isi Label tidak diketik langsung oleh user, tetapi diatur oleh blok program.

Tips penamaan

Awalan txt membantu kita mengingat komponen TextBox. Awalan lbl membantu kita mengingat komponen Label.

Alur Data Project

Project ini punya alur yang jelas: input, simpan, lalu output. Pertama, user mengetik nama di TextBox. Kedua, aplikasi menyimpan isi TextBox ke dalam global variable. Ketiga, aplikasi mengambil isi variabel dan menampilkannya di Label dalam bentuk sapaan.

Alur ini penting karena banyak aplikasi berjalan dengan pola yang mirip. Bedanya, data yang disimpan bisa berupa nama, angka, pilihan menu, skor, atau status.

Yang perlu diingat

Data tidak otomatis pindah dari TextBox ke Label. Kita harus membuat Blocks yang mengambil, menyimpan, menggabungkan, lalu menampilkan data tersebut.

Desain UI yang Dibutuhkan

Aplikasi Sapaan tidak membutuhkan banyak komponen. Justru, UI yang sederhana membuat user langsung paham apa yang harus dilakukan.

Di layar, user melihat judul, kolom untuk mengetik nama, tombol Sapa!, dan area hasil. Jika urutan komponen jelas, user tidak perlu menebak cara memakai aplikasi.

Urutan yang nyaman

Judul di atas, input di tengah, tombol setelah input, lalu hasil di bawah tombol. Urutan ini mengikuti alur kerja user.

Komponen dan Nama Internal

Nama komponen yang jelas membuat Blocks lebih mudah dibaca. Jika tombol masih bernama Button1, kalian harus mengingat sendiri fungsinya. Jika namanya btnSapa, fungsinya langsung terlihat.

Pada project ini, komponen utamanya adalah txtNama, btnSapa, dan lblHasil. Komponen ini akan sering muncul saat kalian menyusun Blocks.

Hati-hati

Nama komponen di Designer harus konsisten dengan yang dipakai di Blocks. Jika salah memilih komponen, hasil aplikasi bisa berbeda dari rencana.

Mengatur Properties

Properties membantu membuat tampilan lebih jelas. Untuk TextBox, bagian pentingnya adalah Hint. Hint adalah teks petunjuk yang muncul sebelum user mengetik.

Untuk Button, ubah teksnya menjadi Sapa! agar user tahu tombol itu digunakan untuk menampilkan sapaan. Untuk Label hasil, kalian bisa membuat teks awal seperti “Hasil sapaan muncul di sini”.

UI yang baik

User tidak perlu bertanya “ini kolom untuk apa?” atau “tombol ini ngapain?”. Petunjuk singkat di tampilan bisa membuat aplikasi jauh lebih mudah dipakai.

Peta Blocks

Blocks sesi ini bisa dibaca sebagai cerita pendek. Pertama, buat variabel kosong. Kedua, saat tombol Sapa! ditekan, ambil isi TextBox dan simpan ke variabel. Ketiga, gabungkan kata “Halo,” dengan isi variabel, lalu tampilkan hasilnya di Label.

Dengan peta ini, kalian bisa memahami kode sebelum menyusun bloknya. Jadi kalian tidak hanya menyalin blok, tetapi tahu fungsi tiap bagian.

Kalimat logika

Ketika tombol Sapa! diklik, simpan teks dari txtNama ke global nama, lalu set lblHasil.Text menjadi “Halo, ” + global nama + “!”.

Langkah 1: Membuat Variabel

Blok initialize global nama to "" dipakai untuk membuat variabel bernama nama. Nilai awalnya adalah teks kosong, karena saat aplikasi baru dibuka, user belum mengetik nama apa pun.

Variabel ini disiapkan sejak awal supaya bisa dipakai ketika tombol Sapa! ditekan. Kalau variabel belum dibuat, kalian tidak bisa memakai blok set global nama atau get global nama dengan rapi.

Kesalahan umum

Jangan memakai nama variabel yang terlalu umum seperti x. Gunakan nama yang menjelaskan isinya, misalnya nama.

Langkah 2: Menyimpan Input

Saat user menekan tombol Sapa!, aplikasi perlu mengambil isi TextBox. Isi itu dibaca dari txtNama.Text. Setelah itu, data disimpan ke global nama.

Inilah bagian yang membuat aplikasi “mengingat” data user selama aplikasi berjalan. Jika user mengetik “Alya”, isi global nama menjadi “Alya”. Jika user mengganti input menjadi “Raka” lalu menekan tombol lagi, isi variabel berubah menjadi “Raka”.

Perhatikan urutan

Ambil data dari TextBox dulu, lalu simpan ke variabel. Jika urutannya tidak jelas, hasil di Label bisa tidak sesuai dengan input terakhir.

Langkah 3: Menggabungkan Teks

Agar sapaan terlihat natural, kita tidak hanya menampilkan nama. Kita perlu menggabungkan teks tetap dengan isi variabel. Blok join dipakai untuk menyusun kalimat seperti Halo, Budi!.

Bagian “Halo, ” dan “!” adalah teks tetap. Bagian tengahnya diambil dari get global nama, yaitu isi variabel yang sudah disimpan dari TextBox.

Contoh

Jika global nama berisi “Nisa”, maka hasil join menjadi Halo, Nisa!.

Melihat Keseluruhan Logika

Slide ini menjadi tempat untuk screenshot Blocks lengkap. Saat kalian melihat rangkaian penuh, cek apakah semua bagian sudah tersambung dengan urutan yang benar.

Project ini sebaiknya memakai variabel secara jelas: simpan input ke global nama, lalu ambil global nama untuk membuat output. Dengan begitu, konsep variabel benar-benar terlihat.

Catatan penting

Kalau Label hanya diisi langsung dengan txtNama.Text, aplikasi memang bisa menampilkan nama, tetapi konsep menyimpan data ke variabel belum terlihat kuat. Untuk sesi ini, pastikan variabel dipakai.

Menguji Alur Aplikasi

Simulasi di kiri meniru alur project: user mengetik nama, menekan tombol, lalu hasil muncul. Di App Inventor, alur ini dibuat menggunakan komponen TextBox, Button, Label, dan global variable.

Coba masukkan beberapa nama berbeda. Jika hasil berubah mengikuti input, berarti aplikasi sudah bersifat dinamis. Ini adalah tanda bahwa aplikasi tidak hanya menampilkan teks tetap.

Test case sederhana

  • Input: Budi → Output: Halo, Budi!
  • Input: Nisa → Output: Halo, Nisa!
  • Input kosong → Output perlu diperhatikan, apakah masih nyaman dibaca?

Membaca Logika Blocks

Sebelum menekan Run atau mencoba di Companion, biasakan membaca Blocks sebagai kalimat. Pada contoh ini, event dimulai dari tombol Sapa! yang diklik.

Baris pertama di dalam event menyimpan isi txtNama.Text ke variabel. Baris kedua menampilkan kalimat sapaan di lblHasil.Text. Jika kalian bisa membaca alur ini, debugging akan jauh lebih mudah.

Kebiasaan bagus

Setiap kali membuat Blocks, tanyakan: inputnya dari mana, disimpan di mana, dan outputnya muncul di mana?

Debugging Aplikasi Sapaan

Debugging dimulai dari gejala. Jika Label kosong, fokus pada bagian output. Jika sapaan tidak lengkap, fokus pada blok join. Jika nama tidak berubah, fokus pada cara variabel diisi.

Jangan langsung membongkar semua Blocks. Ubah satu bagian, tes lagi, lalu lihat apakah masalahnya berubah. Cara ini membuat kalian lebih cepat menemukan penyebab bug.

Tips developer

Uji dengan nama pendek seperti “Budi” dulu. Setelah berhasil, baru coba nama lain atau input kosong.

Mulai Berpikir tentang Validasi

Program dasar biasanya menjalankan apa yang kita tulis, tanpa menebak maksud user. Jika user belum mengetik nama, TextBox berisi teks kosong. Saat digabungkan, hasilnya bisa menjadi Halo, !.

Ini bukan berarti aplikasinya rusak total. Ini menunjukkan bahwa program belum punya validasi input. Materi validasi dengan kondisi akan berguna di sesi-sesi selanjutnya.

Untuk sekarang

Pastikan project utama berjalan dulu: input bisa dibaca, variabel bisa menyimpan, dan Label bisa menampilkan hasil.

Pengembangan dengan TextToSpeech

Challenge ini membuat aplikasi terasa lebih interaktif. Setelah sapaan tampil di Label, aplikasi juga bisa membacakannya menggunakan TextToSpeech.

TextToSpeech adalah komponen non-visible. Artinya, komponen tidak terlihat oleh user di layar, tetapi bekerja di belakang layar untuk menghasilkan suara.

Tips

Gunakan kalimat yang sama dengan Label agar hasil teks dan suara konsisten. Jangan membuat dua kalimat berbeda jika belum diperlukan.

Menambahkan Suara dengan Rapi

Jika kalian menambahkan TextToSpeech, usahakan bloknya tetap mudah dibaca. Jangan membuat teks sapaan dua kali dengan isi yang berbeda. Cara yang rapi adalah membuat sapaan yang sama untuk Label dan TTS.

Pada level ini, kalian boleh mengikuti instruksi guru untuk struktur blok yang dipakai. Yang penting, TextToSpeech membacakan sapaan berdasarkan nama yang user ketik.

Testing suara

Pastikan volume perangkat aman dan tidak mengganggu teman satu kelas. Tes suara secukupnya.

Literasi Digital: Data Pribadi

Walaupun project ini sederhana, kita tetap perlu membiasakan diri menjaga data. Nama panggilan untuk latihan aman digunakan. Namun, menggabungkan nama lengkap dengan data lain seperti nomor HP, alamat, atau sekolah bisa menjadi informasi pribadi yang sebaiknya tidak dimasukkan sembarangan.

Developer yang baik tidak hanya membuat aplikasi berjalan, tetapi juga memikirkan data apa yang benar-benar diperlukan.

Prinsip aman

Gunakan data secukupnya. Untuk project latihan, data dummy atau nama karakter sudah cukup.

Live Testing

AI2 Companion membantu kalian melihat apakah aplikasi benar-benar nyaman dipakai di layar HP. Kadang tampilan di Designer terlihat rapi, tetapi saat diuji di HP ukuran komponen terasa kurang pas.

Untuk project ini, fokus testingnya adalah apakah input dapat diketik dan apakah output berubah sesuai data terbaru. Coba beberapa nama agar kalian yakin program tidak hanya bekerja untuk satu contoh saja.

Jika tidak berubah

Cek lagi apakah event btnSapa.Click sudah berisi blok untuk mengubah lblHasil.Text.

Checklist Berhasil

Output minimum memastikan konsep utama sudah tercapai. Untuk sesi ini, konsep utamanya bukan hanya “Label berubah”, tetapi juga “data disimpan ke variabel lalu dipakai kembali”.

Jika semua poin sudah terpenuhi, kalian boleh mencoba challenge seperti menambahkan TextToSpeech atau mempercantik tampilan. Namun, jangan lompat ke challenge sebelum logika utama benar-benar berjalan.

Prioritas

Aplikasi sederhana yang alurnya jelas lebih baik daripada aplikasi banyak fitur tetapi konsep variabelnya tidak terlihat.

Merapikan Project

Sebelum dikumpulkan, pastikan project yang kalian kirim adalah versi terakhir. Cek kembali Designer dan Blocks agar tidak ada komponen penting yang tertinggal.

Nama project yang jelas membantu guru dan kalian sendiri menemukan file dengan cepat. Kalau diminta mengirim link, pastikan link yang dikirim mengarah ke project yang benar.

Tips sebelum selesai

Jalankan satu kali lagi dengan nama yang berbeda. Jika output ikut berubah, berarti aplikasi sudah dinamis.

Menguji dengan Teman

Peer test membantu kalian melihat aplikasi dari sudut pandang user lain. Karena kalian pembuatnya, kalian mungkin merasa semua sudah jelas. Tetapi user baru bisa saja bingung.

Saat teman mencoba, amati tanpa langsung memberi petunjuk. Jika teman tahu harus mengetik nama, menekan tombol, dan membaca hasil, berarti UI kalian sudah cukup jelas.

Feedback yang berguna

Feedback yang spesifik lebih bermanfaat daripada “bagus”. Contoh: “Hint TextBox sudah jelas” atau “Label hasil sebaiknya dibuat lebih besar”.

Yang Sudah Dipelajari

Hari ini kalian membuat aplikasi yang bisa memakai data dari user. Ini adalah dasar penting sebelum masuk ke aplikasi yang menghitung, mengecek kondisi, atau menyimpan daftar data.

Kalian juga mulai belajar membaca alur program: dari input, ke memori, lalu ke output. Kalau alur ini sudah kuat, sesi-sesi berikutnya akan lebih mudah dipahami.

Siap lanjut?

Di sesi berikutnya, data angka akan mulai diproses dengan operator matematika untuk membuat aplikasi yang lebih fungsional.
