Pin Lokasi: Sensor GPS dan Privasi

Aplikasi Pin Lokasi memiliki dua jalur penggunaan. Jika pengguna memberi izin dan sensor menerima data, koordinat GPS dapat ditampilkan. Jika data belum tersedia, pengguna dapat memilih koordinat contoh. Proyek juga menyediakan tombol untuk menghapus informasi lokasi dari layar.

Tujuan pembelajaran

Siswa diharapkan tidak hanya bisa menyalin blok, tetapi juga memahami kapan sebuah aplikasi membutuhkan data lokasi dan kapan data tersebut sebaiknya tidak diakses.

Apa itu GPS?

Sinyal GPS dapat diterima dengan kualitas berbeda. Karena itu, aplikasi perlu membedakan keadaan sensor sudah aktif dengan keadaan koordinat sudah berhasil diterima.

Komponen LocationSensor

Komponen LocationSensor ditempatkan melalui Palette Sensors. Komponen ini tidak tampil langsung di layar aplikasi, tetapi dapat memberikan data bagi Label ketika program menerima pembaruan lokasi.

Mengenal latitude dan longitude

Istilah latitude berarti lintang, sedangkan longitude berarti bujur. Kedua nilai digunakan bersama sebagai koordinat lokasi. Perlu dibedakan dari Altitude yang berhubungan dengan ketinggian.

Membaca contoh koordinat

Pada slide ini, angka digunakan hanya sebagai data contoh. Tidak ada pembacaan lokasi nyata. Dalam proyek MIT App Inventor, koordinat GPS diperoleh dari event LocationSensor1.LocationChanged jika sensor berhasil membaca lokasi dan izin diberikan.

Mengapa aplikasi meminta izin?

Sebagian aplikasi memerlukan lokasi untuk menjalankan fitur utamanya. Namun, tidak semua aplikasi membutuhkan akses yang sama. Dalam pengujian, gunakan izin latihan yang disimulasikan terlebih dahulu sebelum mencoba perangkat asli.

Latihan: kapan akses lokasi diperlukan?

Diskusikan contoh lain dari modul, misalnya layanan pemesanan makanan yang menggunakan posisi untuk pengantaran. Pada aplikasi kamera dan kalkulator, lokasi bukan kebutuhan pokok bagi fungsi dasarnya.

Jika izin ditolak

Penolakan izin bukan kegagalan siswa. Program harus tetap memiliki tampilan status yang jelas dan dapat menyediakan alternatif. Modul menggunakan tombol Lokasi Simulasi agar proyek masih dapat diuji tanpa GPS asli.

Apa itu fallback location?

Modul menggunakan istilah fake GPS atau fallback location sebagai koordinat latihan. Jelaskan kepada siswa bahwa yang berubah bukan posisi ponsel, melainkan angka contoh yang ditampilkan aplikasi.

Membedakan GPS dan simulasi

Perbedaan sumber data sangat penting untuk transparansi. Jika koordinat berasal dari simulasi, aplikasi sebaiknya menampilkan keterangan “Lokasi Simulasi”, bukan “Lokasi GPS”.

Aktivitas mini: menilai kebutuhan izin

Siswa dapat mendiskusikan hasilnya secara berpasangan. Tekankan bahwa sebuah aplikasi harus meminta izin sesuai kebutuhan fitur. Contohnya, aplikasi peta membutuhkan posisi untuk petunjuk arah, sedangkan kalkulator biasa tidak memerlukan lokasi untuk menghitung angka.

Proyek utama: Pin Lokasi

Proyek ini tidak memerlukan peta daring untuk tahap dasar. Cukup gunakan Label untuk menampilkan latitude, longitude, status, dan pesan privasi. Gunakan perangkat Android nyata hanya untuk pengujian GPS yang telah mendapat izin.

Komponen di Designer

Gunakan tabel sebagai acuan penamaan komponen. Penulisan nama yang konsisten akan memudahkan saat memilih event dan property pada editor Blocks. Beberapa gambar modul menggunakan nama berbentuk huruf kapital; sesuaikan dengan nama yang benar di Designer.

Contoh tampilan proyek

Atur letak tombol Cek Lokasi, Lokasi Simulasi, dan Hapus Lokasi agar mudah dibedakan. Tampilkan informasi asal data secara jelas agar pengguna tidak mengira koordinat simulasi sebagai koordinat nyata.

Dua variabel koordinat

Variabel global digunakan untuk menyimpan latitude dan longitude dari sensor maupun simulasi. Nilai awal berbentuk teks “Belum tersedia” agar tidak terkesan aplikasi sudah memperoleh lokasi.

Alur aplikasi

Status awal dibuat dengan Screen1.Initialize. Tombol Cek Lokasi mengaktifkan sensor, sedangkan event LocationChanged baru menampilkan data ketika pembaruan diterima. Tombol simulasi dan hapus merupakan alur terpisah.

Blocks: pengaturan awal

Membuat sensor tidak aktif pada awal aplikasi memberi kontrol kepada pengguna. Koordinat belum boleh ditampilkan sebelum sensor menerima data atau pengguna memilih simulasi.

Blocks: tombol Cek Lokasi

Pada perangkat sungguhan, sistem mungkin meminta izin lokasi ketika fitur digunakan. Jika pengguna memberikan izin, sensor dapat mulai membaca posisi. Jika tidak, aplikasi tidak dapat memperoleh koordinat GPS.

Blocks: event LocationChanged

LocationChanged dijalankan saat LocationSensor menerima pembaruan posisi. Nilai latitude dan longitude yang diterima event dimasukkan ke variabel global dan ditampilkan. Setelah berhasil, status diubah menjadi “Lokasi berhasil diperoleh”.

Blocks: lokasi simulasi

Modul menentukan koordinat simulasi sebagai angka contoh. Dengan mematikan sensor saat simulasi dipilih, angka tersebut tidak langsung tertimpa oleh pembaruan GPS pada saat latihan.

Blocks: hapus lokasi

Perhatikan bahwa menghapus koordinat dari layar dan variabel bukan berarti menghapus semua data lokasi yang mungkin tersimpan pada layanan lain. Dalam proyek dasar ini, fitur Hapus Lokasi mengosongkan tampilan dan nilai variabel aplikasi.

Simulasi Pin Lokasi

Simulasi mengikuti urutan event dalam modul: pengguna menekan Cek Lokasi, menentukan izin, lalu data diterima pada event LocationChanged. Jika izin ditolak atau data belum ada, angka tidak muncul. Lokasi Simulasi menggunakan koordinat tetap yang ditentukan program. Tidak ada permintaan posisi asli pada browser.

Membandingkan pilihan pengguna

Minta siswa membandingkan output dua jalur: sensor nyata dan data simulasi. Jangan hanya memeriksa angka. Perhatikan juga status, sumber data, dan tindakan setelah tombol Hapus Lokasi dipilih.

Jaga privasi lokasi

Untuk pembelajaran, tidak perlu mengumpulkan lokasi rumah atau perjalanan siswa. Jika pengujian GPS tidak memungkinkan, gunakan data simulasi. Guru dapat memeriksa hasil aplikasi tanpa mengetahui posisi asli siswa.

Tantangan tambahan

Tantangan ini memperkuat dua hal: informasi yang jelas kepada pengguna dan alur berpindah mode. Berikan label yang benar pada setiap hasil agar koordinat simulasi tidak disalahartikan sebagai lokasi GPS.

Pengujian dan debugging

Debugging tidak selalu berarti mencari blok yang hilang. Periksa juga apakah perangkat sudah mendapat izin, apakah event LocationChanged berjalan, dan apakah sensor perlu dinonaktifkan ketika berpindah ke mode simulasi atau setelah menghapus tampilan.

Daftar pemeriksaan proyek

Lakukan uji pada Android fisik jika diizinkan dan memungkinkan. Perolehan koordinat GPS dipengaruhi perangkat serta lingkungan. Untuk membuktikan fitur dasar pada situasi terbatas, hasil dari data simulasi dapat dipakai sesuai ketentuan guru.

Refleksi

Siswa dapat menjawab dengan contoh dari aplikasi yang dibuat. Jawaban sebaiknya menjelaskan peran izin, perbedaan sumber data, dan alasan menjaga privasi, bukan hanya menyebutkan nama tombol.

Rangkuman Sesi 36

Keterampilan utama sesi ini adalah mengelola data sensitif secara bertanggung jawab. Program yang baik tidak hanya mampu menerima informasi lokasi, tetapi juga memberi pilihan dan keterangan yang jelas kepada pengguna.
